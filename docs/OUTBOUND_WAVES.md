# 出库作业与电商波次

## 当前可操作

- 出库单详情展示订单、取消、分配和实际拣货数量。待分配量为订单量减取消量和已分配量。手工分配从同仓、同货主、同物料的实际可用批次里选库存与数量；订单填写的批号或日期同时约束自动分配。取消只扣未分配量。
- 网页新单整单分配齐后，可以按货位和批次逐条确认拣货。同一条分配记录可以分次拣。复核支持主条码单件累加、包装条码按包装档案换算，以及按箱保存商品和数量。耗材料号用「包装耗材」分类，可记录使用的纸箱物料。
- 复核后可以整单直接发货。扫箱发货时，扫描最后一箱才完成出库过账，重复扫描不重复扣库存。
- 波次页可在全仓或指定货位组内试算。指定货位组与分配规则的货位范围取交集，且仍受货主、批次、效期及库存状态约束。勾选「必须全量分配」后，任一单有缺量时整波次回滚。

## 组波分析、短通道与补货设计

首版入口为「出库作业 → 组波分析」。可以筛选并反复分析待分配单，从预设备用拣货组选择空货位，一键生成临时货位组和波次移库单，打印后按实到量确认，再手工放行整波分配。首版使用一货位一 SKU，每个方案内同一 SKU 对应一个货位。容量不足时可减少订单或选择容量更大的货位。自动分配开关、跨组拆拣和已确认方案的原地改版为后续能力，首版可撤销后重新分析。

### 订单先进入待分析池

- 仓库可设置默认全量货位组，并关闭自动分配。订单进入后可带出默认组作为兜底去向，仍处于未分配状态，库存保持可用。分析结果保存为建议，确认方案时才锁定订单归属和所需补货来源，实际出库分配在放行时执行。
- 首版按当前仓库、货主、创建时间、客户、单据类型及订单标识筛选未分配订单。平台渠道、活动编号、截单时间、每波最大单量和件数可随字段补齐后启用。取消量从有效需求中扣除，已取消和已有库存分配的订单不进入普通待分析池。
- 建议把「自动分配库存」作为独立开关，首版默认关闭。后续开启时，以「方案已确认、订单符合策略、货位组已启用、补货已到位」为触发条件。特殊单据始终走人工处理。

### 分流规则与试算口径

| 优先顺序 | 去向 | 判定与作业方式 |
| --- | --- | --- |
| 1 | 全量组人工处理 | 冷链、危险品或配置为「仅走全量组」的特殊标识触发硬限制。整张单隔离出活动组和短通道，即使商品组合命中也不自动组波、补货或分配。操作人从适用的全量组货位处理。全量组没有符合温区、危险品分类或其他要求的货位时，进入异常队列。 |
| 2 | 单品活动组 | 同货主、同 SKU 的单品单达到可配置的订单数门槛后推荐成组。有效明细只有一个不同 SKU 即属单品单，允许一单多件。 |
| 3 | 短通道 | 对剩余普通订单比较 SKU 组合带来的新增整单覆盖。建议初始上限 20 个 SKU、目标覆盖率 80%～90%，由仓库调整。全单有效 SKU 都在组内才计为覆盖。相近覆盖率下优先选占位少、补货工作量低的方案。 |
| 4 | 全量组常规处理 | 组合覆盖不了的单据，以及经主管确认改路的缺货单，整单回全量组。全量组仍无法满足时保留缺货原因，供后续补货或人工处理。 |

页面分别显示组合覆盖、现有库存可齐套、预计补货后可齐套三组数据，并展示分母。比如普通订单 1,000 张，先将 300 张同款单品单建议走活动组，剩余 700 张里有 595 张的所有有效 SKU 都在推荐的 18 个 SKU 内，短通道组合覆盖率为 85%。最终可放行订单数按共享库存、指定批次、效期、货位容量和订单优先级重新校验。试算时同一批库存可用量随拟满足需求逐笔扣减。

组波页允许调整推荐 SKU、货位组和订单去向，调整后立即重算。特殊单据的限制在确认方案、生成补货、手工分配和自动分配时均由后端校验，人工处理也要从符合要求的全量组货位选库存。跨组拆拣和集货合单留作独立作业类型，首版短通道按整单齐套放行。

### 货位组与商品货位关系

- 货位组分为全量组、活动组、短通道组，可配置启用、禁用、默认全量组、自动分配，以及临时组的有效时段。启用前校验货位均属于当前仓库且可用。禁用后退出新方案候选；已有任务由主管完成或取消后退出。
- 允许删除从未使用且无引用的组。已有历史单据、有效 SKU 绑定、库存或未完成波次和移库任务时，需解除对应关系或先完结作业；历史引用保留，使用禁用来退役。禁用默认全量组前先更换默认组。
- 主管可从分析结果一键生成活动组或短通道组，并从预设的备用拣货组选择空货位，生成「仓库、货主、商品、货位、货位组」的对应关系。提交前展示货位码、可用容量和推荐 SKU，支持人工调整。同一货位同时被其他有效方案占用时提示冲突，保留原绑定。
- 首版临时组可优先按一货位一 SKU 安排，同 SKU 可按容量拆到多个货位。同一个位置的不同批次按仓库混放规则校验。活动结束后，先处理剩余库存并完成移库过账，再结束绑定、释放货位。

### 重分析、补货和波次放行

| 当前进度 | 重分析与库存处理 |
| --- | --- |
| 分析草稿 | 可反复重分析、调整条件或更换货位组。保存新版本，并记录操作人、时间和差异。 |
| 方案已确认，补货未执行，出库未分配 | 先撤销或调整相关补货任务、释放对应占用，然后重分析。提交前重查订单状态，避免同一订单被不同操作人重复确认。 |
| 已部分或全部补货，出库未分配 | 可重分析。已执行的移库仍以实际库存位置为准，重新计入目标组可用量。货物确需退回或调往新组时另开移库单。 |
| 已分配或进入后续作业 | 普通重分析排除该单。尚未拣货时可由有权限的人员按现有流程释放分配，再回待分析池。已开始拣货、复核或发货的订单走对应异常流程。 |

1. **生成移库单。** 主管确认波次方案后按 SKU 计算缺口，缺口＝本波有效需求－目标组符合订单条件的可用量，最低为零。分配来源批次时校验货主、质量、批次、效期、专属限制和已有占用，目标货位校验容量及混放。补货单保留波次号、来源位、目标位、SKU、批次、计划数量、实到数量及状态。生成时对来源批次做补货占用，避免同一批货同时被另一波次或普通出库分配。
2. **打印并执行。** 按来源货位顺序打印补货作业清单，展示单号或作业条码、来源位、目标位、SKU、批次、计划数量和实到记录栏。打印、重打都只生成作业凭证。现场搬完按实到数量确认；整单都实到时可一键确认完成，少到或批次不符时先记录差异，再处理剩余任务。
3. **按实物过账。** 确认时重验来源、目标和批次，原子更新来源位、目标位、批次账和移库流水，并扣减本次补货占用。重复提交返回已处理结果。取消未执行任务释放剩余占用；已经过账的移库保留原记录，实物退回后通过新单反向过账。
4. **放行波次。** 补货实到后重新计算目标货位组可用量，整波齐套才能使用现有波次分配。差异明确到订单、SKU、批次和缺量，由主管决定补齐或把受影响订单整单改走全量组。波次分配与补货完成分别留痕，拣货人员只接收到已满足放行条件的任务。

### 实施顺序与验收

1. **分析与货位组管理。** 实现待分析池、全量组默认值、方案重算、商品组合推荐、特殊单隔离，以及组启停和 SKU 货位关系。验收订单进来时库存占用为零，反复试算可调整分流，冷链或危险品即使命中短通道也只进入全量组人工队列。
2. **补货闭环。** 实现按批次占用、生成并打印移库单、实到确认及补货后波次放行。验收打印不改库存、部分实到只过账实到量、整单一键完成不重复过账，以及实物已移后重分析能从新位置正确计算。
3. **按现场数据再启用自动化。** 跟踪整单覆盖率、补货次数、波次等待时间和拣货耗时，稳定后再按仓库、货位组或模板开放自动分配，并保留异常转人工。

## 电子面单的获取时机

默认采用**复核装箱后取号**。多箱、称重计费和包装规格未定的单据，箱码、重量和件数到装箱后才确定。建议以箱为单位保存承运商、运单号、面单状态和取号时间。箱内商品或包装变动时重新确认面单，需要时撤销原号。

对已确定单箱、规格和承运商的电商订单，可按渠道启用**波次前预取号**，用于预打印。订单取消、地址变更或临时拆多箱时，需要作废或补取。取号成功不代表已发货，实际出库完成后再回传平台。每次请求按「平台订单＋箱码＋承运商」防重，重打优先使用原单号。

平台接口接入需要实际的商家和承运商授权，本轮仅落实 WMS 内部箱码和发货流程。Amazon 的接口允许按包裹生成面单，Shopify 的履约接口支持随履约提交或后续更新运单信息。 [Amazon 包裹面单接口](https://developer-docs.amazon.com/sp-api/reference/generateshiplabels) · [Shopify 履约与运单](https://shopify.dev/docs/api/admin-graphql/latest/connections/fulfillmentorderconnection)
