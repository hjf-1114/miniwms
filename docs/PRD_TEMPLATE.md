# MiniWMS PRD 页面记录模板 v1.0

> 定稿 2026-11-05 · 用户确认口径：**载体 1A / 范围 2A / 读者 3D / API 与数据模型 4 单列一章 / 工作方式 5 是 / 交付 6 Markdown**。
> 本文件是**规范**，不是内容；实际记录写入 `docs/PRD_SOURCES.md`，最终 PRD 由素材库生成并另起独立版本文件（如 `docs/PRD_v1.0.md`）。
> 本模板与 `DEVELOPMENT.md`（开发记录）、`README.md`（对外功能口径）职责分离：那两份保持精简，不因 PRD 准备而膨胀。

---

## 1. 三层写法（对应读者 D：质检演示 / 内部开发 / 业务评审 兼顾）

| 层 | 标记 | 回答的问题 | 典型内容 | 主要读者 |
|---|---|---|---|---|
| 业务层 | `[业务]` | 为什么做、谁用、解决什么 | 业务背景、痛点、适用角色与场景、业务价值、主线流程 | 客户 / 业务方评审、质检演示 |
| 功能层 | `[功能]` | 页面上有什么、能做什么 | 查询条件、列表列、按钮、字段表、状态机、规则、异常提示 | 三类读者共读 |
| 实现层 | `[实现]` | 代码怎么落、怎么验 | 端点、数据表、字段类型与默认值、事务、算法、测试用例、提交哈希 | 内部开发交付 |

- 每个小节开头标层标记；同一小节混写时逐段标。
- **「用途与背景」必须写到业务层**，不能只写一句「管理货主」。
- 三层不重复叙述同一事实：业务层讲动机，功能层讲交互，实现层讲落点。

## 2. 标准页面模板（11 项，顺序固定，逐页照抄骨架）

```markdown
### 2.N <中文页面名>（`<文件名>`）

**[业务] 用途与背景**
<为什么存在、解决什么业务问题、在 5 层蓝图哪一层、由哪个里程碑引入、后续哪些里程碑增强过>

**[业务] 适用角色与场景**
<谁在什么场景下用；角色若由系统自定义则如实说明，不编造预置岗位>

**[功能] 页面布局**
- 查询条件：…
- 列表字段：…
- 行操作 / 页操作：…
- 分页：…

**[功能] 表单字段表**
| 字段 | 控件 | 必填 | 校验 | 默认值 | 来源 / 联动 |
|---|---|---|---|---|---|

**[功能] 子表 / 弹窗**
<独立弹窗的列表列、录入项、可增删规则；没有则写「无」>

**[功能] 业务规则与状态机**
<编号列出：唯一约束、状态流转、删除保护、联动换算、隔离校验…>

**[功能] 异常与提示**
| 触发 | 前端提示 | 后端响应 |
|---|---|---|

**[实现] 关联单据与数据流向**
<被哪些表/单据引用，数据从哪来、流到哪去；删除前检查覆盖范围如实写>

**[实现] 权限**
<当前代码真实鉴权状态，不写不存在的权限码>

**[功能] 与其他页面的关系**
<下拉数据源、跳转变签、工作台内嵌、共用组件>

**[实现] 验收要点**
<对应测试文件与可观察行为>

**[实现] 对应里程碑与提交**
<里程碑编号 + 已知提交哈希；无把握的哈希不编造，指向 DEVELOPMENT.md / git log>
```

## 3. 字段表规范

- **一行一字段**；字段多时用小标题分组，但不省略字段。
- 「控件」写：文本框 / 文本域 / 数字 / 日期 / 下拉 / 地区三级联动 / 复选 / 自动生成编码输入 / 是否下拉。
- 「必填」写 是 / 否；「校验」写**后端真实规则**（长度、枚举、数值下限、唯一、外键存在且启用），前端 `type=email`、`required` 只作补充注明。
- 「默认值」写 DDL 或 create 接口的默认值，不写「无」。
- 「来源 / 联动」写：主数据带出、可覆盖、实时联动、自动换算、下拉数据源端点。
- 前端 `help` 文案与后端校验不一致时**以代码为准**，并在「异常与提示」注明。
- 状态名、按钮、标签一律**中文**；英文值放在括号内，如「启用 active」。

---

## 4. 状态机与业务规则规范

- 状态流转用 `→` 列出，注明触发动作、是否可逆、是否影响历史单据。
- 「删除保护」「唯一约束」「多货主隔离」「体积自动换算」等必须写明**触发条件 + 错误信息原文**。
- 只读接口、批量操作、事务边界（`BEGIN IMMEDIATE`）、零行保留等如与该页相关，写进「关联单据与数据流向」。

## 5. 记录规范（沿用华 WMS PRD 工作方式，用户确认「是」）

1. **存疑项先编号提问**，确认后才写入；**不在文档内嵌 TODO / 待确认字样**。
2. 每批 **1–2 页**增量交付；先分析取证 → 确认 → 再改文档。
3. 状态名 / 按钮 / 标签一律**中文**。
4. 每版 PRD **独立新文件**，不覆盖历史版本；素材库新增内容**作独立章节追加，不重写已有内容**。
5. 每次更新后**自审 + 第三方视角交叉审阅**（对照代码逐条核对字段、端点、提示语）。
6. 增量需求**每次 1–2 条**，区分主业务与辅助业务，不擅自改已有设计。
7. **结构化文字列出页面要素，不画原型图**。

## 6. 取证源与一致性约束

| 优先级 | 取证源 | 取什么 |
|---|---|---|
| 一级 | `web_app/*.html` | 查询条件、列表列、按钮、表单字段、弹窗、前端提示 |
| 一级 | `routes_*.py` | 端点、入参校验、默认值、状态流转、错误信息原文、HTTP 码 |
| 一级 | `main.py` | DDL、字段类型与默认值、索引、幂等 ALTER 迁移 |
| 一级 | `constants.py` | 状态机枚举、流水类型、理由码、单据标识位 |
| 二级 | `tests/test_*.py` | 验收要点、边界用例 |
| 二级 | `DEVELOPMENT.md` / `README.md` | 里程碑归属、对外口径 |

- **不写代码中不存在的功能**；权限、校验、默认值必须与当前代码一致。
- 同一事实在多处出现时，以 `PRD_SOURCES.md` 该页记录为准，其他文档引用而非复制。
- 发现代码与既有文档不一致时，先如实记录代码现状，再单独提出，不擅自改代码。

## 7. 进度表维护

- `PRD_SOURCES.md` 第 1 章维护「21 页覆盖进度表」，标 `已记录 / 待补` 与章节锚点。
- 正文只写已完成页；**未写页不在正文留占位**，避免文档里堆空壳。
- 每完成一页：更新进度表 → 追加该页独立章节 → 更新末章「记录变更日志」。
- 每完成一个后续里程碑，按同一模板同步追加该里程碑涉及的新页 / 改动页。
