### 1.4 术语

| 术语 | 含义 |
|---|---|
| 货主（owner） | 委托仓储的货权方；系统的第一隔离维度，多货主并存 |
| 库位（location） | 库存的物理落点；库存账三维度之一 |
| 储区（zone） | 仓库内的温区 / 功能分区，混放默认与温区约束的载体 |
| 货位组（location group） | 库位的逻辑分组，承载拣货顺序与容量上限 |

| DN | 出库单（Delivery Note），出库单据头 |
| 批次（batch） | 一批同源货的标识；关键批次信息一致即同一档案 |
| 序列号（serial） | 单件实物的唯一标识，M33 起有独立台账 |
| 指定客户 | M23 引入：某批库存只供特定客户使用 |
| FEFO | 先到期先出，M35 波次分配的默认批次策略 |
| I1 / I2 / I3 | 库存三项硬校验：主账 vs 流水 / 明细 vs 流水 / 主账 vs 明细 |

| 3 库存账与核算 | 库存账、批次库存、库存调整、库存转移、账实核对 | 5 | 库存账、库存调整 |

| 6 系统入口 | 登录、工作台、首页 | 3 | 工作台 |

### 2.2 核心业务闭环

```
① 建基础资料        货主 → 物料 → 仓库 → 储区 → 库位 → 货位组
                          ↓
② 收货入库          ASN 建单 → 验收（生成批次号）→ 上架（推荐 + 规则拦截）
                          ↓
③ 库存账            三层账：主账 / 批次明细 / 流水（I1 I2 I3 硬校验）
                          ↓
④ 出库发货          DN 建单 → 波次分配（FEFO）→ 拣货 → 复核 → 发货
                          ↓
⑤ 盘点与调整        盘点方案 → 冻结 → 盲盘 → 差异 → 调整单审核过账
                          ↓
⑥ 运营复盘          经营报表（收发 / 周转 / 利用率）+ 工作量统计 + GSP 报表
```

### 2.3 三条贯穿全系统的硬约束

1. **多货主隔离**：任何带 `owner_id` 的数据，按货主注入查询条件；
   上下文缺失一律拒绝执行，不做隐含放行。
2. **库存三层账一致**：主账、批次明细、动作流水三者必须互相平账，
   校验不通过不允许继续作业（无豁免）。
3. **数量变更唯一入口**：手工改数量只能走库存调整单，审核过账才生效；
   收货、发货、移库、盘点差异都不能直接改账。

### 3.1 货主管理（owners.html）

#### [业务] 用途与背景

多货主（3PL）是本系统的核心模型：每个货主拥有独立的物料档案与库存，
后续收货、拣货、库存账、盘点等所有单据都挂货主维度。**没有货主档案就无法区分物权、
无法按货主拆分库存账、也无法校验客户 / 供应商归属。**
本页是货主维度的**唯一建档入口**，也是全系统多货主隔离校验的参照表。

货主档案除基础信息外，还承载两类合规与商务信息：
- **资质证照**（营业执照、医疗器械经营许可等，可挂多张，含有效期）——用于 GSP 场景的合规追溯；
- **合作起止时间**——标识合作关系有效期。

#### [业务] 适用角色与场景

| 场景 | 说明 |
|---|---|
| 引入新货主 | 建档：编码、名称、联系方式、省市区与详细地址 |
| 资质管理 | GSP / 医疗器械场景维护证照及有效期，可挂多张 |
| 合作变更 | 联系人与地址变更走编辑；合作结束改为停用，不删除 |
| 建单参照 | 收货、出库、物料、客户、供应商页的货主下拉数据源均来自本页 |

#### [功能] 页面布局

- **查询条件**：关键字（占位「编码/名称搜索」，模糊匹配编码与名称）、
  状态下拉（全部状态 / 启用 / 停用）、「查询」按钮。
- **列表字段**：ID、编码、名称、联系人、电话、邮箱、状态、操作。
- **行操作**：编辑、证照、停用 / 启用（按当前状态切换文案）、删除。
- **页操作**：+ 新建货主。
- **分页**：上一页 / 下一页 + 「第 N 页 / 共 M 条」，每页 20 条，首末页自动禁用。

#### [功能] 表单字段

| 字段 | 控件 | 必填 | 校验 | 默认值 |
|---|---|---|---|---|
| 编码 | 文本框（留空自动生成，前缀 `OW`） | 是 | 非空、≤32 字符、全表唯一 | 空 |
| 名称 | 文本框 | 是 | 非空、≤128 字符 | 空 |
| 联系人 / 电话 | 文本框 | 否 | 去首尾空格 | 空 |
| 邮箱 | 邮箱控件 | 否 | 仅前端控件校验，后端只去空格 | 空 |
| 所在地区 | 省 / 市 / 区三级联动，整行 | 否 | 拆成三个字段提交 | 空 |
| 详细地址 | 文本框 | 否 | 去首尾空格 | 空 |
| 备用地址 | 文本框 | 否 | 去首尾空格 | 空 |
| 授权仓库 | 文本框 | 否 | 去首尾空格，**自由文本，非仓库外键** | 空 |
| 经营范围 | 文本框，整行 | 否 | 去首尾空格 | 空 |
| 备用字段 1 / 2 | 文本框 | 否 | 去首尾空格 | 空 |
| 合作起始 / 合作截止 | 日期选择器 | 否 | 去首尾空格，按字符串存储 | 空 |
| 备注 | 文本域，整行 | 否 | **保留用户换行** | 空 |

状态不在新建表单内，由行操作切换（启用 ⇄ 停用，可逆）。

#### [功能] 子表：货主证照管理

- 列表列：类型、证号、发证机构、有效期（起 ~ 止）、操作（删）；无数据显示「暂无证照」。
- 录入行：证照类型（**必填**，为空时前端不提交）、证号、发证机构、起始日期、截止日期 + 「+ 添加」。
- 一个货主可挂**多张证照**；删除仅删该证照行，不影响货主档案。

#### [功能] 业务规则

1. **编码唯一**：新建命中已有编码 → 409「货主编码已存在」；编辑改编码排除自身。
2. **状态流转**：启用 ⇄ 停用，可逆。停用不影响历史单据；但**停用货主不能再挂新物料**。
3. **删除保护**：名下有物料即拒绝，409「该货主名下还有 N 个物料档案，禁止删除；
   请先转移或停用」。删除前有二次确认。
4. **部分更新**：只更新请求体中出现的字段；空请求体 → 400「没有可更新的字段」。
5. **默认值**：新建默认启用，其余字段缺省为空串。
6. **无级联删除**：删除货主不删除其证照记录。

#### [功能] 异常与提示

| 触发 | 前端提示 | 后端响应 |
|---|---|---|
| 编码 / 名称为空 | 表单拦截 | 400 `code 必填` / `name 必填` |
| 长度超限 | — | 400 `code 最长 32 字符` / `name 最长 128 字符` |
| 编码重复 | 显示后端错误 | 409 `货主编码已存在: xxx` |
| 删除时名下有物料 | 二次确认后失败提示 | 409 `该货主名下还有 N 个物料档案，禁止删除；请先转移或停用` |
| 货主不存在 | 显示后端错误 | 404 `货主不存在` |
| 证照类型为空 | 前端不提交 | 400 `cert_type 必填` |

#### [实现] 接口与数据

- 接口：`GET/POST /api/owners`、`GET/PUT/DELETE /api/owners/{id}`、
  `GET/POST /api/owners/{id}/certs`、`DELETE /api/owners/{id}/certs/{cert_id}`。
- 数据：主表 `owner`；证照子表 `owner_cert`；被 `product` / `customer` / `supplier` /
  `asn` / `dn` / `stock` 引用。
- **删除前检查只覆盖物料档案**，其他引用表未做检查。
- 权限：本页接口**未挂强制权限装饰器**，仅靠数据权限上下文做货主隔离。
- 验收要点：创建校验、重复编码 409、分页 / 关键字 / 状态过滤、部分更新、删除保护。

### 3.2 物料管理（products.html）

#### [业务] 用途与背景

物料是 WMS 的核心主数据：收货、拣货、盘点、库存账全部以物料为参照。
M1 建立物料档案与库存挂接；M10 面向电商 / 医药级场景深化出**电商字段**
（条码 / 品牌 / 规格 / 长宽高 / 重量 / 体积 / 保质期天数 / 产地 / 经营范围 /
注册证号 /  hazardous 危险品类型等）、**多层级包装**（包装等级 1–6 级）与
**多条码**；M15 补一键演示数据播种；M20 增加「推荐储区」用于上架推荐；
M31/M32/M33 先后把**司机车辆关联**、**产品类型字典**、**序列号台账**接进物料档案。

物料档案同时承载三个「是否」开关，决定后续作业的校验强度：

| 开关 | 含义 | 影响 |
|---|---|---|
| 是否序列号 | 该物料按单件管理 | M33 起有独立序列号台账；**当前仍是标记位，不强制登记** |
| 是否保质期控制 | 该物料按效期管理 | M19 起批次档案带效期，GSP 报表做效期分级 |
| 推荐储区 | 上架优先落位 | M25 上架推荐的第 2 优先级 |

#### [业务] 适用角色与场景

| 场景 | 说明 |
|---|---|
| 建档 | 编码、名称、单位、分类、默认储区与货主归属 |
| 电商 / 医药字段维护 | 品牌规格、条码包装、注册证与备案人、生产企业与许可证、危险品类型 |
| 尺寸与体积 | 填长宽高自动换算体积；包装层级各自有尺寸 |
| 分类治理 | 分类层级（1–4 级）、产品主分类、**产品类型字典**（M32 起） |
| 货品归属 | 货主下拉为空＝自营；指定货主后仅该货主可见可用 |

#### [功能] 页面布局

- **查询条件**：关键字 + 货主下拉 +「查询」按钮。
- **列表字段**：ID、SKU、名称、条码、品牌、规格、分类、**产品类型**、货主、推荐储区、
  采购价、销售价、当前库存、状态、操作。
- **行操作**：编辑、绑定货位、条码 / 包装、删除。
- **页操作**：+ 新建物料。
- **分页**：上一页 / 下一页 + 「第 N 页 / 共 M 条」，每页 20 条。

#### [功能] 表单字段

| 字段 | 控件 | 必填 | 校验 | 默认值 |
|---|---|---|---|---|
| SKU | 文本框（留空自动生成，前缀 `SKU`） | 是 | 非空、≤64 字符、唯一 | 空 |
| 名称 | 文本框 | 是 | 非空、≤128 字符 | 空 |
| 货号 | 文本框 | 否 | 去空格 | 空 |
| 默认分类 / 单位 | 文本框 | 否 | 去空格 | 「未分类」/「件」 |
| 主条码 / 品牌 / 规格 | 文本框 | 否 | 去空格 | 空 |
| **产品类型** | **字典下拉** | 否 | 取自产品类型字典；**填字典外的值会自动建行** | 未指定 |
| 产品主分类 / 一至四级分类 | 文本框 | 否 | 去空格 | 空 |
| 产地 / 外部编码 / 经营范围 | 文本框 | 否 | 去空格 | 空 |
| 注册证号 / 注册人备案人 / 生产企业 / 生产许可证 | 文本框 | 否 | 去空格 | 空 |
| 温度范围 / 湿度范围 / 危险品类型 | 文本框 | 否 | 去空格 | 空 |
| **是否序列号 / 是否保质期控制** | 下拉（是 / 否） | 否 | — | 否 |
| 备用字段 1 / 2 / 3 | 文本框 | 否 | 去空格 | 空 |
| 重量 / 长 / 宽 / 高 / 体积 | 数字 | 否 | 数字且非负 | 0 |
| 保质期天数 | 数字 | 否 | 整数且非负 | 0 |
| 采购价 / 销售价 | 数字 | 否 | 数字且非负 | 0 |
| 推荐储区 | 下拉 | 否 | — | 未设置推荐储区 |
| 货主 | 下拉（可空） | 否 | 空＝自营 | 自营 |
| 状态 | 下拉 | 否 | 启用 / 停用 | 启用 |
| 备注 | 文本域，整行 | 否 | — | 空 |

**体积联动**：未手填体积但填了长宽高时，前端先做一次换算，后端为权威口径会再算一次。

#### [功能] 子表 / 弹窗

- **绑定货位**：把物料固定到优先库位，供上架推荐使用。
- **条码 / 包装**：多条码维护 + 包装层级（1–6 级）及其尺寸、每箱数量。

#### [功能] 业务规则

1. **SKU 唯一**：新建命中 → 409「SKU 已存在」；编辑改 SKU 排除自身。
2. **货主归属**：货主为空＝自营；指定后该物料仅归属该货主。
3. **体积自动换算**：长 × 宽 × 高（cm³）÷ 10000 → 体积。
4. **产品类型引用（M32）**：产品类型列引用字典编码；填字典外的值会**自动建字典行**
   （继承该货品归属），不阻塞录入。历史自由文本已按原文本回填成字典行，**取值不变**。
5. **删除**：有库存的物料不能物理删除。

#### [功能] 异常与提示

| 触发 | 前端提示 | 后端响应 |
|---|---|---|
| SKU / 名称为空 | 表单拦截 | 400 `sku 必填` / `name 必填` |
| SKU 重复 | 显示后端错误 | 409 `SKU 已存在` |
| 数字字段非法 | 显示后端错误 | 400 `{字段} 必须为数字` / `不能为负数` |
| 货主不存在 | 显示后端错误 | 400 `货主不存在` |
| 长度超限 | — | 400 `sku 最长 64 字符` / `name 最长 128 字符` |

#### [实现] 接口与数据

- 接口：`GET/POST /api/products`、`GET/PUT/DELETE /api/products/{id}`、
  条码与包装子表接口、`GET /api/product-types/dict`（类型下拉）。
- 数据：主表 `product`（含 `product_type` 引用列、`is_serial`、`is_shelf_control`、
  `default_zone_id`）；关联 `product_location`（固定货位）、包装与条码子表。
- 权限：接口**未挂强制权限装饰器**；`product` 在货主隔离表内。

### 3.3 库位管理（locations.html）

#### [业务] 用途与背景

库位是库存的物理落点。库存账以「货主 × 物料 × 库位」记账，收发、移库、盘点、
拣货全部挂在库位上。仓库布局从粗到细分三层：**仓库 → 储区 → 库位**。
储区承载温区与混放默认，库位承载具体货位与可覆盖的混放设置。

库位按**作业功能**分四类，这决定了它出现在哪些作业环节：

| 类型 | 用途 | 出现环节 |
|---|---|---|
| 收货区 | 暂存待上架 | 收货验收（目标位）、上架作业（来源位） |
| 存储区 | 常规存放 | 上架作业（目标位）、拣货（来源位） |
| 拣货区 | 面向拣选 | 拣货（来源位） |
| 退货区 | 退货暂存 | 退货收货 |

#### [业务] 适用角色与场景

| 场景 | 说明 |
|---|---|
| 规划仓库布局 | 按仓库 → 储区 → 库位逐层建立，编码建议体现「巷道-列-层」 |
| 划分作业区 | 按功能选类型，决定该库位参与哪些环节 |
| 设定混放策略 | 库位级覆盖储区默认；留空则继承储区 |
| 容量与体积 | 填长宽高自动算体积库容；容量 0 表示不限 |
| 分组管理 | 库位组（M34）承载拣货顺序与组级容量上限 |
| 布局调整 | **已有库存的库位只能停用，不能删除** |

#### [功能] 页面布局

- **查询条件**：关键字（编码 / 名称）、类型下拉、库位组下拉、仓库下拉、储区下拉
  （储区选项显示「编码 · 名称〔仓库｜温层〕」，仓库变更时联动重画）、查询按钮。
- **列表字段**：ID、编码、名称、所属仓库、储区、货位组、巷道、层、类型、容量、
  体积库容(m³)、条码、混放、状态、操作。
- **行操作**：编辑、停用 / 启用、删除。
- **页操作**：+ 新建库位。

#### [功能] 表单字段

| 字段 | 控件 | 必填 | 校验 | 默认值 |
|---|---|---|---|---|
| 编码 | 文本框（留空自动生成，前缀 `LOC`） | 是 | 非空、≤32 字符、唯一 | 空 |
| 名称 | 文本框 | 是 | 非空、≤128 字符 | 空 |
| 所属仓库 | 下拉 | 否 | 仓库必须存在 | 未指定仓库 |
| 储区 | 下拉 | 否 | 储区必须存在、未停用、与库位同仓 | 不挂储区 |
| 库区 | 文本框 | 否 | 去空格；**历史兼容字段** | 「默认区」 |
| 巷道 / 列 / 层 | 文本框 | 否 | 去空格 | 空 |
| 库位条码 | 文本框 | 否 | 去空格 | 空 |
| 类型 | 下拉 | 否 | 收货区 / 存储区 / 拣货区 / 退货区 | 存储区 |
| 容量 | 数字 | 否 | 数字且非负；0＝不限 | 0 |
| 库位组 | 文本框 | 否 | 留空按编码前缀自动生成；**引用货位组字典编码** | 自动 |
| 长 / 宽 / 高(cm) | 数字 | 否 | 数字且非负 | 0 |
| 混放（产品 / 批号 / 货主） | 下拉 | 否 | 继承储区（留空）/ 禁止 / 允许 | 留空 |
| 状态 | 下拉 | 否 | 启用 / 停用 | 启用 |
| 备注 | 文本域 | 否 | 去空格 | 空 |

#### [功能] 业务规则

1. **编码唯一**：冲突 → 409「库位编码已存在」。
2. **仓库 / 储区一致性**：储区不存在 → 400；储区已停用 → 400「储区已停用，不能挂新库位」；
   储区与库位不同仓 → 400「储区所属仓库与库位所属仓库不一致」。
3. **删除保护**：库位已有库存记录 → 409「该库位已有 N 条库存记录，禁止删除；
   请改用停用」。
4. **体积库容自动计算**：长 × 宽 × 高换算体积库容（m³）；只改部分维度时按
   「新值覆盖 + 旧值补齐」重算。
5. **库位组自动生成与引用**：留空时按编码前缀推导（短横线前的首段，否则前 2 字符），
   并在货位组字典中建行；**已有分组文本原样保留为字典编码，老库位取值不变**。
6. **混放生效值**：库位自身设置 → 继承储区 → 默认禁止（保守口径）。
7. **不按货主隔离**：库位是全系统共享的布局资源。

#### [功能] 异常与提示

| 触发 | 后端响应 |
|---|---|
| 编码 / 名称为空 | 400 `code 必填` / `name 必填` |
| 编码重复 | 409 `库位编码已存在: {code}` |
| 储区停用或跨仓 | 400 `储区已停用，不能挂新库位` / `储区所属仓库与库位所属仓库不一致` |
| 容量或尺寸非法 | 400 `capacity 必须为数字` / `{字段} 不能为负数` |
| 删除时已有库存 | 409 `该库位已有 {n} 条库存记录，禁止删除；请改用停用(status=inactive)` |

#### [实现] 接口与数据

- 接口：`GET/POST /api/locations`、`GET/PUT/DELETE /api/locations/{id}`、
  `GET /api/locations/groups`（库位组下拉）。
- 数据：`location`（关联 `warehouse` / `zone` / `location_group`）；
  库存四表按 `location_id` 引用，删除保护读取库存行数。
- 验收要点：编码唯一、储区一致性、删除保护、体积自动计算、混放生效值。

### 3.7 仓库管理（warehouses.html）

#### [业务] 用途与背景

仓库是**运营方的资产**，全系统共享、不绑定货主。它同时是系统的**数据隔离单元**。

本系统采用「中央控制库 + 按仓业务库」：仓库档案里的「独立数据文件」决定该仓的业务数据

|---|---|---|
| 留空 | 与全部仓库共用主库（**默认，下载即用**） | 演示、小规模 |
| 填 `xxx.db` | 该仓业务数据物理隔离到独立文件 | 多仓正式运营 |

切仓通过顶栏仓库选择器完成，选中的仓以请求头传递；未带仓头时用默认仓，

| 场景 | 说明 |

| 建立仓库 | 编码、名称、地址与联系人 |
| 物理隔离 | 填项目目录内的 `.db` 相对路径，该仓数据独立存放 |
| 切仓作业 | 顶栏选择器决定当前操作哪个仓，切仓后所有标签页同步刷新 |
| 布局引用 | 储区、库位挂仓库；收货与出库单记录来源仓库 |

#### [功能] 页面布局

- **查询条件**：关键字（编码 / 名称 / 联系人）、状态下拉、查询按钮。
- **列表字段**：ID、编码、名称、地址、联系人、电话、**数据隔离**、状态、操作；
  数据隔离列显示「独立库 + 路径」或「共用主库」。

- **页操作**：+ 新建仓库。

#### [功能] 表单字段

| 字段 | 控件 | 必填 | 校验 | 默认值 |
|---|---|---|---|---|
| 编码 | 文本框（留空自动生成，前缀 `WH`） | 是 | 非空、≤32 字符、唯一 | 空 |
| 名称 | 文本框 | 是 | 非空、≤128 字符 | 空 |
| 地址 / 联系人 / 电话 | 文本框 | 否 | 去空格 | 空 |
| 独立数据文件 | 文本框 | 否 | 必须位于项目目录内、必须以 `.db` 结尾 | 共用主库 |
| 备注 | 文本域 | 否 | 去空格 | 空 |

#### [功能] 业务规则

1. **编码唯一**：冲突 → 409「仓库编码已存在」。
2. **数据文件路径校验**：越界 → 「仓库数据文件路径必须位于项目目录内」；
   后缀不对 → 「仓库数据文件必须以 .db 结尾」。
3. **自动建库**：保存后自动创建该 SQLite 文件并同步货主与仓库主数据。
4. **删除保护**：跨**全部业务库文件**检查收货单与出库单的来源仓库引用，
   命中 → 409「仓库已被收货单引用（ASN {单号}），不可删除」/
   「仓库已被出库单引用（DN {单号}），不可删除」。
5. **控制面中央库**：仓库、角色、用户等控制面数据存中央库，不随业务仓切换。

#### [功能] 异常与提示

| 触发 | 后端响应 |
|---|---|
| 编码 / 名称为空 | 400 `code 必填` / `name 必填` |
| 编码重复 | 409 `仓库编码已存在: {code}` |
| 数据文件路径非法 | 400 `仓库数据文件路径必须位于项目目录内` / `仓库数据文件必须以 .db 结尾` |
| 删除时已被单据引用 | 409 `仓库已被收货单引用（ASN {code}），不可删除` |

#### [实现] 接口与数据

- 接口：`GET/POST /api/warehouses`、`GET/PUT/DELETE /api/warehouses/{id}`、
  `GET /api/scope/warehouses`（可切换仓清单）。
- 数据：`warehouse`（**控制面中央库**）；`zone.warehouse_id`、
  `location.warehouse_id`、`asn.source_warehouse`、`dn.source_warehouse`、
  `owner_warehouse` 引用。
- 验收要点：编码唯一、路径校验、跨库删除保护、按仓分库可用。

### 5.3 库存三层账

| 表 | 粒度 | 用途 | 关键约束 |
|---|---|---|---|
| `stock` | 货主 × 物料 × 库位 | 库存主账 | **粒度永不改**；qty / allocated_qty |
| `stock_batch` | 货主 × 物料 × 库位 × 批次维度 | 批次级明细 | qty / allocated_qty；与流水按批次维度平账 |
| `stock_movement` | 动作流 | 变更留痕 | qty_delta / allocated_delta / ref_type / 批次维度 / designated_customer_id / goods_property / stock_status / expiry_date |
| `batch_location` | 批次 × 库位 | 批次实物分布 | 与上架流水同步 |

**三项硬校验（无豁免、无灰度）**：

| 编号 | 校验 | 容差 |
|---|---|---|
| I1 | `stock.qty` == Σ`stock_movement.qty_delta`（按货主·物料·库位） | 1e-9 |
| I2 | `stock_batch.qty` == Σ`stock_movement.qty_delta`（按批次全维度） | 1e-9 |
| I3 | `stock.qty` == Σ`stock_batch.qty`（按货主·物料·库位） | 1e-9 |

| `external_doc_type_dict` | 外部单据类别与改位 / 驳回原因码字典 |

## 6. 权限与数据隔离

### 6.1 三层权限模型

| 层 | 载体 | 生效范围 |
|---|---|---|
| **功能权限** | 角色权限码（`资源:动作`，支持 `*` 与 `资源:*` 通配） | 挂在端点装饰器上；**当前仅用户 / 角色 / 授权三个域实际生效**（权限码 `user:manage`） |
| **数据范围** | `warehouse_scope` / `owner_scope` 标志 + 明细授权行 | SQL 层注入 `owner_id` 条件；`all` 必须**显式**给出，不靠空配置隐含放行 |
| **业务关系** | `owner_warehouse` | 可见仓 × 可见货主的**交集**，再与实际数据关系求交 |

### 6.2 隔离口径

| 规则 | 说明 |
|---|---|
| 上下文缺失 | 一律拒绝执行（403），不做隐含放行 |
| 全部权限（ALL） | **必须显式给出**；`scope=all` 会清空明细授权行 |
| 共享数据 | 归属为空的行（如共享承运商、全局货位组）对所有已解析上下文可见 |
| 货主维度表 | 带 `owner_id` 的表在查询时自动注入 `owner_id IN (...)` |
| 按 ID 访问 | 详情 / 编辑 / 删除同样过守门，**不只列表过滤** |
| 匿名演示 | `MINIWMS_ALLOW_ANONYMOUS` 默认开（下载即用）；生产部署须设为 0 |

### 6.3 数据隔离单元

仓库是**物理隔离单元**：中央控制库存账号、角色、仓库等控制面数据；
业务库按仓存放。仓库的 `db_path` 留空＝共用主库，填写项目目录内 `.db` 相对路径
＝该仓业务数据物理隔离到独立文件。**零登记 / 不带仓头＝不启用按仓隔离**。
